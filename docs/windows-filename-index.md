# Windows 文件名索引

内置全盘文件名搜索由 `nohrs-indexer` Windows 服务提供。服务只读访问本机固定 NTFS 卷，命名管道仍使用协议版本 2；本次更新没有改变缓存格式、依赖或安装账户。

本次同时修正服务读取搜索请求时将关键词长度从 `u16` 错写为 `usize` 的问题。64 位服务原先会插入额外零字节，导致关键词与返回数量错位；新增测试覆盖多关键词、中文和返回数量，确保请求正文与既有协议逐字节一致。

## 更新行为

- 服务启动时读取 MFT 全量基线，并回放扫描期间的 USN 变化，再发布首份搜索快照。
- 运行中每轮等待约 2 秒后读取 USN 日志，合并同一 MFT 编号的变化，只读取涉及的当前记录。覆盖新建、重命名、目录移动、删除、硬链接和文件元数据更新。
- 目录移动后重新生成路径树，因此子项路径和用户目录过滤一起更新。
- 搜索读取不可变的共享快照。后台更新或手动重建时保留上一份快照，完成后替换；正在执行的搜索可以继续使用原快照。
- 服务停止会唤醒首次快照等待者，并在 MFT 分块读取之间取消后台扫描。

本版不保存跨服务重启的 USN 游标或 MFT 基线。服务重启时重新读取全量基线，校准停机期间的变化；首次快照准备期间请求需要等待。

## 兜底

- 日志 ID 改变、游标过期或倒退、未知日志格式、单轮超过 256 批或 32,768 条不同记录时，保留旧快照并安排后台全量重建，失败后间隔约 30 秒重试。
- 常驻属性列表按文件主记录与全部扩展记录一起读取，校验引用和序列号后整批更新，包含扩展记录中的大小与硬链接名称。缺失、损坏、序列号不匹配、非常驻属性列表或嵌套扩展列表使用同一重建路径，整批保留旧数据。
- 启动时日志追赶失败，会再取一次全量基线，暂时禁用增量并安排重试。
- 无法打开现有 USN 日志的卷使用每 30 分钟全量更新，也可手动重建。服务不会创建或修改卷的 USN 日志。
- 当前卷枚举范围和用户目录权限过滤保持既有逻辑。

## 性能边界

增量磁盘读取按变化记录执行；名称缓冲压缩和内存搜索快照构造仍需遍历卷内名称，尚未实现完全按变化数量更新。各卷由同一低优先级后台线程处理，轮询等待不代表严格的可见性时限。

2026-11-14 在本机 D 盘约 189 万条名称上直接触发更新的测试：基线约 3.25 秒，新建、目录移动、删除各约 0.35–0.40 秒。这些数值不含后台轮询等待，不代表 UI 端到端延迟或其他机器性能。

同日在已安装服务的真实命名管道上验证：改名、硬链接、删除约 2.3–3.0 秒可见（包含轮询等待）。手动重建时连续查询仍返回旧快照，8 秒观察期间单次查询最长约 16 毫秒。首次新建测试与服务启动基线重叠，约 5 秒可见；这些仅为本机观测值。

## 验证

```powershell
cargo test --release -p nohrs-pages -p nohrs-indexer --quiet -- --test-threads=1
cargo clippy --release -p nohrs-indexer --all-targets
cargo build --release -p nohrs -p nohrs-indexer
```

实盘测试需要原始卷读取权限，在仓库 `target` 目录下创建专用临时目录并自行清理：

```powershell
cargo test --release -p nohrs-indexer real_ -- --ignored --nocapture --test-threads=1
```

实盘验证覆盖创建、重命名、硬链接、移动、删除、旧快照可用、游标失效后的重建、重新初始化发现离线变化、停机取消及系统卷连续增量跟踪。常规测试中这些测试默认忽略；搜索性能基准也默认忽略。

## 应用到已安装服务

编译只生成仓库下的程序，不会替换已运行的服务。需在获准重启后，用新版 `prime-files-indexer.exe --install --allow <原安装用户 SID>` 更新已安装服务；其安装路径通常为 `C:\Program Files\Prime Files Indexer`。协议兼容既有界面，服务重启后先建立新基线。
