# 搜索索引设置

设置 › 搜索索引（`Índice de busca`）把整机文件名搜索的取舍集中到一页，布局参照 Everything 的选项窗口：顶部三个标签页，下面是列表和开关。

## 三个标签页

| 标签页 | 内容 |
|---|---|
| 磁盘（Unidades） | 列出本机固定磁盘，逐盘开关是否参与搜索；显示当前索引里的名字数或索引服务的条目数；右上角显示索引状态。 |
| 排除项（Exclusões） | 排除隐藏项、排除系统项、启用排除列表；排除的文件夹（目录选择器添加）与模式（`*.tmp`、`*~`、`*/node_modules/*`）；"仅包含这些文件"和"排除这些文件"两组扩展名掩码。 |
| 高级（Avançado） | 索引来源（自动 / 本程序 / Everything）、索引状态与"立即重建"、NTFS 即时索引服务（MFT）的安装与开关。 |

## 生效方式

所有选项都是**查询时过滤**：搜索命中之后再按当前配置筛掉，不重建索引、不清空内存里的名字表、不重启索引服务。所以改完立刻生效（下一次按键或下一次搜索），代价是索引里仍然保留被排除的名字（内存与建立时间不变）。

`search.toml` 是配置文件（设置页写入，热加载读回）：

```toml
[indexing]
source = "auto"
volumes = []       # 参与搜索的固定磁盘，例如 ["C:", "D:"]；空 = 全部

[indexing.exclude]
enabled = true     # 下面四个列表的总开关
hidden = false     # 排除隐藏项（含隐藏文件夹里的内容）
system = false     # 排除系统项
paths = []         # 整棵排除的文件夹，例如 ["C:\\Temp"]
globs = []         # 名字或路径模式，例如 ["*.tmp", "*/node_modules/*"]
include_only = []  # 只保留的文件掩码，例如 ["*.pdf"]；空 = 所有文件
masks = []         # 排除的文件掩码，例如 ["*.tmp"]
```

语义细节：

- 路径比较忽略大小写，`/` 与 `\` 等价，结尾分隔符忽略；`C:\Temp` 不会误伤 `C:\Tempo`。相对条目（如 `node_modules`）按目录边界匹配任意位置。
- 模式里含分隔符的按整条路径匹配；不含分隔符的按路径中任意一级名字匹配——所以过滤 `.git` 会把仓库里的整个 `.git` 目录连同内容排除，而不只是名为 `.git` 的那一项。
- 掩码只作用于文件，文件夹永远保留（否则浏览路径会断）。
- 隐藏/系统判定读取 Windows 文件属性，并连同祖先文件夹一起判断：隐藏文件夹里的内容同样被排除。被测项已删除或无权读取时保留该项，不重复查询同一文件夹。
- 这些过滤同样作用于 Everything 来源的结果，以及"跳转栏"（对话框搜索）和独立搜索窗口。

## 常用写法

| 想排除 | 放在哪里 | 填什么 |
|---|---|---|
| 任意位置的 `.git`、`.svn` 目录 | 过滤（Adicionar filtro） | `.git; .svn` |
| `node_modules`、`temp`、`tmp` 这类目录 | 过滤 | `node_modules; temp; tmp` |
| 临时/备份文件 | 排除这些文件（掩码） | `*.tmp; *.temp; *~; *.bak; ~$*` |
| 某个具体目录（连同内容） | 添加文件夹（Adicionar pasta） | 用对话框选目录，写入 `paths` |
| 只在某个父目录下排除 | 过滤（带分隔符的路径模式） | `*/node_modules/*` |
| 所有隐藏项/系统项 | 两个开关 | 打开"排除隐藏项"和/或"排除系统项" |

过滤框可以一次输入多条（分号或逗号分隔），回车或点按钮即加入列表；每种写法都可以在 `search.toml` 的 `[indexing.exclude]` 里手改。

## 和 Everything 的差别

按"只做能真正落地的部分"取舍：

- **没做**内容索引（Content）、属性（Properties）、文件列表（File Lists）、ReFS 标签页：本程序的索引只有文件名，没有正文、属性列和文件列表机制，ReFS 卷的 USN 配置也只属于索引服务内部。这些标签页如果只画界面会变成无效控件。
- **没做**"重新扫描计划 / 缓冲区大小"之类的逐卷设置：索引要么由本进程整盘遍历，要么由索引服务用 MFT + USN 维护，二者都没有逐卷调度器。
- 上面这些以后要来，需要先有对应的后端能力，再补界面。

## 验证

```powershell
cargo test -p nohrs-core   # 配置解析、JSON Schema、九种语言的翻译表
cargo test -p nohrs-pages  # 过滤规则、设置页渲染（含搜索索引三个标签页）
cargo clippy -p nohrs-core -p nohrs-pages --all-targets
```

设置页写入 `search.toml`（`[indexing]` / `[indexing.exclude]`），由热加载送回窗口，和手改配置走同一条路径。
