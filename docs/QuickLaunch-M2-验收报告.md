## 2. 必须修复

### B1. 拖入或选择多个文件时，会静默覆盖已有条目（数据丢失）
- `put_item()` 的语义是“替换”：`retain(|existing| existing.slot != slot)`。
- `drop_paths()` 和右键“新建条目”（`prompt_for_paths` 里 `multiple: true`）把第 n 个文件放进 `slot + n`。只要后面的槽里已经有条目，那个条目就会被**直接替换掉**，没有任何提示。用户只能事后通过 `quicklaunch.toml.bak` 找回，而 .bak 只保留一份。
- 规格 §12.2 写的是“多个文件按顺序占后面的**空槽**”。
- **修复**：新增 `place_items(group, start, items)`：从 `start` 开始，依次把每个条目放进**下一个空槽**，永远不覆盖已有条目。把单个文件拖到一个已有条目的格子上时，也放进它后面第一个空槽，不替换。`put_item` 只留给编辑类调用使用。
- **测试**：slot 3、4 已有条目，选中 3 个文件放进 slot 2，结果应为 2、5、6，原来的 3、4 不变。

### B2. Shift+单击“打开所在位置”在两种情况下看不到结果
`reveal_item()` 直接调用 `explorer_link::request(path)`：
- **主窗口隐藏在托盘时**（Q5 之后这是常态），文件会在看不见的窗口里打开并选中。M1 的 B2 已经为“打开文件夹”修过同一个问题，但这条路径没有用那套逻辑。
- **常驻模式下**，进程里没有资源管理器，`explorer_link` 没有接收方，直接返回 `false`，**什么都不会发生**。
- **修复**：抽出一个统一函数 `open_in_explorer(cx, path)`，“打开文件夹”和“打开所在位置”都调用它：
  - `Mode::Main`：先 `tray::request_show()`，再 `explorer_link::request`；
  - `Mode::Standalone`：在后台先 `ipc::request_open`，失败则用 `current_exe` 启动主程序（`LumaFiles.exe <文件>` 本身支持“打开所在文件夹并选中这个文件”）。

### B3. 健康状态不会随编辑更新
健康结果按 `(分组 id, 槽位)` 存储，每个会话只检查一次。所以：
- 灰色条目通过编辑对话框**改对路径后仍然是灰色**，要重启才恢复；
- 交换或移动条目后，灰色标记留在原来的槽位上，**标到了另一个条目**；
- 新建、拖入的条目永远不会被检查（执行方未决问题 7）。

**修复**：
- `put_item / edit_item`：清除该槽的健康记录，再给这个条目发一次单独的健康检查（走 `quick-launch-icons` 线程）。
- `swap_slots`：交换两个槽的健康记录。
- `move_item_to_group`：把健康记录搬到新的分组和槽位。
- `delete_item / delete_group`：删除对应的健康记录。

**测试**：每种操作至少一个。

### B4. `indexed_icon` 的路径缓冲区可能没有结束符（越界读）
- `windows.rs:96–99` 用 `[0u16; 260]` 存路径，通过 `zip` 拷入。路径的 UTF-16 长度 ≥ 260 时，缓冲区会被**填满，没有 NUL 结束符**，`PrivateExtractIconsW` 会读到缓冲区之外；路径更长时还会被静默截断。
- **修复**：UTF-16 长度 ≥ 260 时直接返回 `None`，并记一条 debug 日志。补一个测试：构造一个 300 字符的路径。

### B5. 违反 `.rules`：用 `let _ =` 丢弃错误
- `quick_launch/view.rs:459、466`：`WeakEntity::update` 的结果被丢弃。改用 `.log_err()`。其中 466 行的 `close.update(cx, |_, _| {})` 是空操作，直接删掉。
- `launch/windows.rs`：图标 GDI 清理代码有 11 处 `let _ =`，而且同一套释放逻辑在 3 个分支里各写了一遍。规格 §8.4 要求“句柄统一用 RAII”。
  - **修复**：为 DC、HBITMAP、HICON 各写一个小型 guard，在 `Drop` 里释放，释放失败用 `.log_err()` 记录。
  - `DrawIconEx` 失败时返回 `None`：现在会返回一张全透明的图，被当成正常图标缓存下来。
- `launch.rs:407`：`let _ = (path, index, edge);`。改为把参数命名成 `_path` 等。

### B6. 新增：标题栏锁定按钮（BoBO 手测时提出）
从桌面或资源管理器往快速启动里拖文件时，要先点别的窗口，快速启动窗口会因为失去焦点而自动隐藏，导致没法拖入。按规格 v2.5 §11.1，在标题栏右侧加一个“锁定”按钮：复用 `window.topmost` 字段；锁定后窗口保持在最前，并且不会因失去焦点、启动条目或打开所在位置而隐藏；只有 Esc 和热键会隐藏它。测试和手测见 §11.1。

## B. 必须修

- **R1 `move_item_to_group` 中变量遮蔽，把别的条目的记录搬走了。**
  函数内部用 `let slot = first_free_slot(target);` 遮蔽了参数 `slot`，之后 `move_health(state, (&from_id, slot), (&to_id, slot))` 和 `move_usage(cx, (from_id, slot), (to_id, slot))` 的**源槽位用的都是新槽位号**。
  后果：把 A 组 slot 5 的条目移到 B 组时（假设 B 组第一个空槽是 0）：
  - 被搬走的是 **A 组 slot 0 那个不相干条目**的健康状态和使用次数；
  - 被移动条目原来在 slot 5 的记录留在原地，下一个放进 A 组 slot 5 的条目会继承它（灰色标记和使用次数都会错位）。

  两个测试都是从 slot 0 移到 slot 0，所以没有发现这个问题。
  **修复**：把新槽位命名为 `new_slot`，源用原来的 `slot`。**测试**：把 A 组 slot 5 的条目移到空的 B 组（落在 slot 0），A 组 slot 0 另有一个条目并带有健康状态和使用次数。断言：A 组 slot 0 的两项记录保持不变；slot 5 的记录被搬到 B 组 slot 0；A 组 slot 5 不再有任何记录。
